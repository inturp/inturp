# Survey backend (Firebase project `vet-charted`)

- Function `submitSurvey` (region europe-west1) receives each submission from the survey page, validates it against
  `survey-schema.json` (generated by `showcase/build_survey.py`) and stores it in the **named Firestore database `survey`**
  (the project's `(default)` database is a different, Datastore-mode database and is not touched).
- `firestore.rules` denies every client read and write. Answers can only be read with an admin identity: the Firebase
  console (Firestore > database `survey` > `survey_responses`) or `node export.mjs` (CSV).
- Protections: allowed web origins only, JSON only, 24 KB limit, strict schema, honeypot, minimum time spent,
  4 submissions per hour and 12 per day per visitor (salted hash of the IP, never the IP itself), 3000 per day overall,
  at most 3 function instances.

## Deploy (after changing questions.json or index.js)
    python3 ../../build_survey.py            # regenerates survey-schema.json
    npm install
    firebase deploy --only functions:survey,firestore:survey --project vet-charted

`IP_PEPPER` (a random secret) lives in `.env`, which is git-ignored. Create it once: `IP_PEPPER=<64 random hex chars>`.
Changing it only resets the rate-limit counters.
